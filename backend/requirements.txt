# Direct dependencies, bounded.
#
# WHAT WAS WRONG. This file listed eighteen bare package names. `pip install -r`
# therefore resolved to whatever was newest on the day it ran, which means the
# "frozen" evidence state the thesis reports figures against was not
# reproducible: two people installing from the same commit a month apart get
# different libraries, and for the machine-learning tier that can mean different
# numbers.
#
# THE BOUNDS ARE RANGES, NOT EXACT PINS, and that is deliberate. Freezing every
# transitive package would make this a lock file, and a lock file has to be
# regenerated for every security patch — which for a departmental project run by
# whoever inherits it means it stops being regenerated at all. A floor keeps the
# behaviour the code was written against; a ceiling at the next major keeps a
# breaking release from arriving unannounced. Security patches inside the range
# still install.
#
# THE MACHINE-LEARNING TRIO IS PINNED HARDER. scikit-learn, numpy and pandas are
# capped below the next MINOR, not the next major, because tree construction and
# random-number generation can change across a scikit-learn minor and move R²
# and MAE — the figures Chapter Four reports. The numbers are only claimed
# within a stated environment; see backend/app/ml/model_baseline.json for the
# exact versions they were recorded under, and docs/REPRODUCIBILITY.md for how
# to re-derive them.
#
# For a deployment that needs an exact set, generate a lock from a clean
# environment (docs/REPRODUCIBILITY.md gives the command). One is deliberately
# not committed here: it would be a lock produced on one developer's Python
# version and silently wrong for any other.
